The System Philosophy

Everything your hostel needs.
One connected system.

Conventional hostel administrations struggle with desynchronized spreadsheets, paper mess registers, and inaccurate vacancy counts. HostelHub connects every touchpoint through a strict relational database architecture.

01 / The Challenge

Disconnected Silos

Student admissions live in one file, room vacancy counts in another, and mess registrations on physical registers. Double room allocations and unbilled dining fees become inevitable.

02 / The Architecture

Centralized Relational Core

15 relational tables enforce referential integrity using cascading foreign keys, automated bed-count triggers, and PL/SQL stored procedures. Room allocation changes immediately update floor inventory and student status in real-time.

03 / The Outcome

Seamless Integrity

Wardens, mess caterers, and students access a unified single source of truth. Zero ghost rooms, accurate bed counts, transparent annual fee billing, and instant analytical query benchmarks.

Q1_Active_Room_Allocations.sql 
SELECT s.reg_no, s.full_name, r.room_number, h.hostel_name
FROM Student s
JOIN RoomAllocation ra ON s.student_id = ra.student_id
JOIN Room r ON ra.room_id = r.room_id
JOIN Floor f ON r.floor_id = f.floor_id
JOIN Block b ON f.block_id = b.block_id
JOIN Hostel h ON b.hostel_id = h.hostel_id
WHERE ra.status = 'Active'
LIMIT 5;
